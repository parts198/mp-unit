# Unified FBS stock

Центральный виртуальный FBS-склад для Ozon, Wildberries и Яндекс Маркета.

## Принцип

`mp-unit` является единственным источником истины по остатку.

Публикуемый остаток:

```text
available = max(0, physical_stock - active_reservations - safety_buffer)
```

Новый заказ на любой площадке создаёт идемпотентный резерв в локальной БД. После изменения `available` новое значение ставится в очередь публикации для всех трёх маркетплейсов.

## Почему сначала dry-run

Боевой сервер `/opt/ozon-unit` содержит реальную SQLite-базу, API-токены и сервисы синхронизации. GitHub-репозиторий не содержит полной серверной реализации, поэтому включать запись в кабинеты до интеграции с боевым сервисом нельзя.

Рекомендуемый порядок запуска:

1. Применить `schema.sql` к копии `ozon_unit.db`.
2. Импортировать SKU магазина «Сувениры» и построить mapping Ozon/WB/Yandex.
3. Получать новые FBS-заказы трёх площадок в read-only и прогонять их через `UnifiedFbsEngine.reserve_order()`.
4. Сверить расчётный остаток с фактическими заказами минимум на тестовой группе SKU.
5. Подключить marketplace adapters; по умолчанию `UNIFIED_FBS_WRITE_ENABLED=0`.
6. Включить запись для 3–5 тестовых SKU.
7. После проверки включить весь ассортимент.

## Обязательные инварианты

- один `(marketplace, order_id, order_item_id, sku_id)` резервируется только один раз;
- физический остаток и резерв не могут стать отрицательными;
- отмена до отгрузки освобождает резерв;
- отгрузка уменьшает `physical_stock` и закрывает резерв;
- возврат не увеличивает `physical_stock`, пока товар физически не принят обратно;
- маркетплейсы не используются как master-остаток;
- каждая публикация и ошибка должна логироваться.

## Интеграционные адаптеры

Нужны три адаптера с одинаковым контрактом:

```python
fetch_new_orders(cursor) -> list[OrderEvent]
publish_stocks(items) -> PublishResult
fetch_current_stocks(items) -> dict[MappingKey, int]
```

Сами HTTP-запросы должны жить в существующем серверном приложении, где уже хранятся секреты и настройки магазинов. Не добавлять API-ключи в Git.

## Переключатели

Рекомендуемые переменные окружения:

```text
UNIFIED_FBS_ENABLED=1
UNIFIED_FBS_WRITE_ENABLED=0
UNIFIED_FBS_SHOP_ID=7
UNIFIED_FBS_POLL_SECONDS=10
UNIFIED_FBS_DEFAULT_BUFFER=0
```

`UNIFIED_FBS_WRITE_ENABLED=0` означает: заказы читаются, локальные расчёты и очередь публикации формируются, но реальные PUT/POST остатков на маркетплейсы не выполняются.
